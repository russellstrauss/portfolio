General Principles of Web Accessibility

Web accessibility is the practice of ensuring that our content and applications contain no barriers across the web and across all members of our society. Web accessibility generally aims to provide accomodations for humans with disabilities, medical considerations, or lack of access to socioeconomic status. If our society is to demand that these technologies are required by all for everyday participation, it's only fair that we provide ways for everyone to access it.

WCAG: Web Content Accessibility Guidelines

The World Wide Web Consortium (W3C) is the primary international standards organization that drafts and expands technical speciications for the World Wide Web. The W3C was founded in 1994 by Time Berners-Lee. The W3C serves as an open forum for developing and maintaining standards across the web.

The W3C maintains many open standards including Web Content Accessibility Guidelines (WCAG). The WCAG is a set of recommendations for improving web accessibility. WCAG 2.0 was released in December 2008 and became an international standard in October 2012. WCAG 2.2 was released in October 2023. WCAG Version 3 is currently under development.

POUR

Web accessibility is guided by four foundational principles defined by the Web Content Accessibility Guidelines:

  1. Perceivable
  2. Operable
  3. Understandable
  4. Robust

Perceivable: Easy to Perceive

Perceivable means accessible across differences in human senses.Users must be able to perceive the information being presented. Content cannot be invisible to all of a user's senses and must not rely on a single sensory method such as sight or hearing. Perceivable includes requirements for audio/video captions, text description for images, and levels of contrast.

WCAG Conformance Levels for Perceivability

Level A Level AA Level AAA
  • text alternatives
  • adaptable content
  • color contrast
  • text resizing
  • enhanced contrast
  • sign language interpretation

Real World Examples

  • A screen reader announces meaningful descriptions for images
  • A color-blind user understands errors without relying on color
  • A low-vision user zooms text without breaking the layout

Operable: Easy to Operate

User interface components and navigation should be able to be controlled. Users must be able to interact with the interface regardless of input method or device.

WCAG Conformance Levels for Operability

Level A Level AA Level AAA
  • keyboard access
  • no keyboard traps
  • visible focus state
  • consistent navigation
  • no time limits
  • enhanced navigation

Real World Examples

  • A keyboard-only user navigates all controls
  • A user skips repetitive navigation with a Skip to Main Content button
  • A motor-impaired user avoids time-sensitive interactions

Understandable: Easy to Understand

It should be easy for people to complete tasks and understand the information presented. This can be done with consistent design, understandble language, and a tolerance for human error.

WCAG Conformance Levels for Understandability

Level A Level AA Level AAA
  • language identification
  • clear labels
  • consistent navigation
  • error identification
  • simplified language
  • extended help

Real World Examples

  • Users understand form instructions easily
  • Error messages explain what went wrong
  • Navigation behaves consistently across pages

Robust: Compatible Across Device-Types and Technologies

Content and applications should be compatible with a wide array of web browsers, assistive technologies, operating systems, and versions. Standards in code & content structure and universal formats help to successfully build across device types.

Robustness includes:

  • Be programmatically determinable (HTML elements and attributes are correct)
  • Follow standards (HTML, CSS, ARIA)
  • Avoid patterns that are technically correct but break assistive tools
