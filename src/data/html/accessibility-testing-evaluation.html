Accessibility Testing & Evaluation

Comprehensive accessibility testing combines automated tools, manual testing, and user testing with people who have disabilities. A multi-layered approach ensures the most thorough evaluation of your digital products.

Automated Testing Tools

Automated tools can quickly identify many accessibility issues, but they cannot catch everything. Use them as part of a comprehensive testing strategy.

Browser Extensions

  • WAVE (Web Accessibility Evaluation Tool): Visual feedback on accessibility issues
  • axe DevTools: Comprehensive automated testing with detailed reporting
  • Lighthouse: Built into Chrome DevTools, includes accessibility audits
  • Pa11y: Command-line tool for automated accessibility testing
  • Accessibility Insights: Microsoft's tool for web and Windows apps

What Automated Tools Catch

  • Missing alt text on images
  • Color contrast issues
  • Missing form labels
  • Missing heading structure
  • ARIA misuse
  • Keyboard navigation issues (some)

What Automated Tools Miss

  • Meaningful alt text quality
  • Logical content flow
  • Context-dependent issues
  • Complex interaction patterns
  • User experience barriers

Manual Testing

Manual testing is essential for catching issues that automated tools cannot detect.

Keyboard-Only Navigation

  • Navigate the entire site using only the keyboard (Tab, Shift+Tab, Enter, Space, Arrow keys)
  • Verify all interactive elements are reachable
  • Check for keyboard traps
  • Verify focus indicators are visible
  • Test custom components and widgets

Screen Reader Testing

Test with at least one screen reader to understand the experience for blind and low-vision users.

  • NVDA (Windows, free): Popular open-source screen reader
  • JAWS (Windows, paid): Most widely used screen reader
  • VoiceOver (macOS/iOS, free): Built-in Apple screen reader
  • TalkBack (Android, free): Built-in Android screen reader

Visual Testing

  • Test at 200% browser zoom
  • Test with browser default font sizes
  • Test with high contrast mode enabled
  • Test with color blindness simulators
  • Test on different screen sizes and resolutions

User Testing with People with Disabilities

Nothing replaces testing with actual users who have disabilities. They can identify issues that automated tools and manual testing miss.

Recruiting Testers

  • Work with disability advocacy organizations
  • Use accessibility testing services
  • Include people with disabilities in your regular user research
  • Ensure diverse representation (different disabilities, assistive technologies, experience levels)

What to Test

  • Core user journeys and tasks
  • Form completion
  • Navigation and wayfinding
  • Content comprehension
  • Error recovery
  • Custom interactions and widgets

Testing Checklist

Page Structure

  • Single h1 per page
  • Proper heading hierarchy
  • Landmark regions present (header, nav, main, etc.)
  • Skip links functional
  • Page title is descriptive and unique

Images

  • All images have appropriate alt text
  • Decorative images have empty alt=""
  • Complex images have detailed descriptions
  • Images of text are avoided when possible

Forms

  • All inputs have associated labels
  • Required fields are clearly indicated
  • Error messages are clear and helpful
  • Form validation is accessible
  • Form can be completed with keyboard alone

Links and Buttons

  • Link text is descriptive and meaningful out of context
  • Buttons have clear labels
  • All links and buttons are keyboard accessible
  • Focus indicators are visible
  • No keyboard traps

Color and Contrast

  • Text meets contrast requirements (4.5:1 for normal text)
  • Information is not conveyed by color alone
  • Focus indicators are visible
  • Works in high contrast mode

Multimedia

  • Videos have captions
  • Audio has transcripts
  • Media players are keyboard accessible
  • No auto-playing audio

Continuous Testing

Accessibility testing should be integrated into your development workflow, not just done at the end.

  • Run automated tests in CI/CD pipeline
  • Include accessibility in code review checklists
  • Test new features before release
  • Regular comprehensive audits (quarterly or bi-annually)
  • Monitor and fix issues found by users

Documentation and Reporting

Maintain documentation of your testing process and findings.

  • Keep records of accessibility audits
  • Document known issues and remediation plans
  • Maintain an accessibility statement
  • Track accessibility metrics over time
  • Share findings with the development team
