Fundamental Accessibility Practices

These core practices form the foundation of accessible web development. Implementing these from the start of a project is more effective and cost-efficient than retrofitting accessibility later.

Semantic HTML

Use HTML elements for their intended purpose. Semantic HTML provides meaning and structure that assistive technologies can interpret.

  • Use heading tags (h1-h6) in proper hierarchy to structure content
  • Use lists (ul, ol) for list content, not just styling
  • Use proper form elements (input, label, fieldset, legend)
  • Use landmark elements (header, nav, main, aside, footer)
  • Avoid using divs and spans when semantic elements exist

Alternative Text for Images

All images must have appropriate alt text that conveys the same information or function as the image.

  • Decorative images: Use empty alt="" to indicate the image is decorative
  • Informative images: Provide concise, descriptive alt text
  • Functional images: Describe the function (e.g., "Search" for a search icon button)
  • Complex images: Provide detailed descriptions in surrounding text or longdesc
  • Avoid redundant phrases like "image of" or "picture of"

Keyboard Navigation

Ensure all interactive elements are accessible via keyboard alone.

  • All links, buttons, and form controls must be keyboard accessible
  • Provide visible focus indicators (outline or border changes)
  • Ensure logical tab order matches visual order
  • Implement skip links for main content
  • Avoid keyboard traps where users cannot escape
  • Support standard keyboard shortcuts (Enter, Space, Arrow keys)

Color and Contrast

Don't rely solely on color to convey information, and ensure sufficient contrast.

  • Maintain contrast ratio of at least 4.5:1 for normal text (Level AA)
  • Maintain contrast ratio of at least 3:1 for large text (18pt+ or 14pt+ bold)
  • Use icons, text, or patterns in addition to color
  • Test with color blindness simulators
  • Ensure focus indicators are visible regardless of color

Form Accessibility

Forms must be properly labeled and provide clear error messaging.

  • Associate labels with form controls using the "for" attribute or implicit labeling
  • Use fieldset and legend for related form groups
  • Provide clear, specific error messages
  • Indicate required fields clearly
  • Provide helpful instructions and examples
  • Allow users to review and correct errors before submission

Content Structure

Well-structured content is easier to navigate and understand.

  • Use a single h1 per page
  • Maintain proper heading hierarchy (don't skip levels)
  • Use lists for list content
  • Break up long content with headings and sections
  • Use paragraphs for text blocks
  • Provide clear, descriptive link text (avoid "click here")

Multimedia Accessibility

Audio and video content must be accessible to all users.

  • Provide captions for all video content
  • Provide transcripts for audio content
  • Provide audio descriptions for video when visual information isn't described in audio
  • Ensure media players are keyboard accessible
  • Allow users to control playback (play, pause, stop)

Responsive and Flexible Design

Content should work across different devices and screen sizes.

  • Use relative units (em, rem, %) instead of fixed pixels
  • Ensure content reflows properly at different zoom levels
  • Test at 200% zoom level
  • Avoid horizontal scrolling
  • Ensure touch targets are at least 44x44 pixels

ARIA When Necessary

Use ARIA (Accessible Rich Internet Applications) to enhance accessibility when HTML alone isn't sufficient.

  • Use ARIA labels and descriptions when native HTML isn't enough
  • Use ARIA roles for custom components
  • Use ARIA states and properties to communicate dynamic content
  • Don't use ARIA when native HTML provides the same functionality
  • Test with screen readers to ensure ARIA is working correctly

Performance and Accessibility

Fast-loading pages benefit all users, especially those with slower connections or assistive technologies.

  • Optimize images and media files
  • Minimize JavaScript and CSS
  • Use lazy loading appropriately
  • Ensure critical content loads first
  • Test on slower connections and devices
