Fundamental Accessibility Practices

These core practices form the foundation of accessible web development. Implementing these from the start of a project is much more effective and cost-efficient than retrofitting accessibility later.

What is Semantic HTML?

Semantic HTML is the practice of using tags that accurately describe the structure of the content being displayed. Use HTML elements for their intended purpose. Semantic HTML is crucial for the correct interpretation and navigation of content by assistive technologies.

For example, <div>'s and <span>'s do not carry any semantic meaning. <div> generically stands for "divide". <div> is a generic block-level element and <span> is a generic inline-level element.

  • Use heading tags (<h1> through <h6>) in proper hierarchy to structure content
  • Use lists (<ul>, <ol>) for list content, not just styling
  • Use proper form elements (<input>, <label>, <fieldset>, <legend>)
  • Use landmark elements (<header>, <nav>, <main>, <aside>, <footer>)
  • Avoid using <div>s and <span>s when semantic elements exist

Alternative Text for Images

All images must have appropriate alt text that conveys the same information or function as the image. The alternative text is an "alternative" to the visual content of the image. alt is an attribute applied to the <img> tag. The alt text should describe the visual content of the image for someone who cannot process the image visually. Screen readers commonly read the alt text aloud to describe the image. For example, a picture of a dog in a field may read, "A large brown dog sniffs dafodils in a sunny park."

A blank alt attribute instructs the screen reader to ignore the image. If the alt attribute is left blank on an important image, the user will not even know that it is present on the page at all. However, for decorative elements that do not carry any meaning, specifying a blank alt attribute is an appropriate way to tell a screen reader to ignore it, when that is the intended use-case.

  • Informative images: Provide concise, descriptive alt text.
  • Functional images: Describe the function (e.g., "Search" for a search icon button).
  • Complex images: Provide detailed descriptions in surrounding text.
  • Avoid redundant phrases like "image of" or "picture of".

Keyboard Navigation

Keyboard navigation is one of the most important aspects of web accessibility, and it should be one of the first aspects of your app that you audit and test. We must ensure all interactive elements are accessible via keyboard alone. Why? Because many people cannot use a mouse. This feature is most important for those with motor disabilities. Some people do not have arms, some people have vision that makes it impossible to see the cursor, some people have neuropathy (like me), some people have carpal tunnel in their wrists, and many others have reasons that make it difficult or impossible to interact with their system using the mouse. Many superusers who do not have a disability prefer to use the keyboard for speed and efficiency. Some just find it easier to use the keyboard. There are times when we simply do not have a mouse and want to interact through the keyboard, so it is imperative that we include this functionality built into our applications. This is typically the first and most basic aspect of accessibility that will be tested. So keyboard controls are important for all of your users!

All links, buttons, and form controls must be keyboard accessible. If it is part of your application, it should be accessible by keyboard control.

Focus Indicators

The focus indicator is the visual feedback system that is built into the browser for navigating the page with the keyboard. It is typically represented by a border or dotted line surrounding the currently selected element.

"
Key Point:

Avoid using css properties outline: 0; or outline: none;, as this breaks focus indicators. The outline property IS the focus indicator.

Tip: If you need to change the outline style, you can update it to reflect your brand identity and design system, but make sure that you test your updates do not break its functionality.

Tab Order

It is crucial for usability to ensure that your keyboard controls follow a logical tab order that matches the visual ordering of your application's UI. Your controls should support the standard keyboard shortcuts such as Enter, Space, Tab, Shift+Tab (backwards), and the Arrow keys.

Skip to Main Content

The Skip to Main Content feature of keyboard navigation is the most important aspect of keyboard controls and the first feature that you should check or implement. Many app's main navigation areas can have huge numbers of links and sub-navs or hierarchies. Don't forget that because the HTTP web protocol is stateless, every time the user navigates to a new page in your app, the tab location is reset. So if your main nav has hundreds of links in it, the user will have to press tab hundreds of times every time a new page is opened. This is the purpose of the Skip to Main Content control. The user should be able to skip to the main content of the page with a single interaction instead of traversing through complex navigations on every new page reload. The nav is generally the first element on the page, but the main content area of the site is where the page's meaningful substance begins.

To implement this feature, you can add a "Skip to Main Content" button which is displayed on the first Tab press. By selecting this button when it appears, the user's tab focus skips all navigation or other unrelated elements between the top of the page and the main content area and travels straight to the main content, allowing the user to interact with the page's true substance right away.

Keyboard Traps

Without a conscientious effort to check and control the flow of the keyboard controls, it's not uncommon for there to be a sink in interaction flow.

In computing, a sink is a destination in data flow where flow terminates and contains no outgoing paths leading out from it, acting as a final collection point for data flow. In other words, a sink is like quicksand where you cannot return once you have entered. These are unintentional traps from which the user cannot escape. It is crucial to test for these sinks because they break the user's ability to navigate your app. In web accessibility, these are called keyboard traps.

A few common causes for keyboard traps can include:

  • Modals & Dialogs: A pop-up UI takes focus without providing a keyboard control to close it. (This site includes a code lightbox—try viewing code in a modal.)
  • Advanced Widgets: Calendars, datepickers, video players, or custom components that improperly handle keyboard focus can suck in the user flow, especially those with large amounts of sub-elements like a calendar.
  • Incorrect Event Handling or JavaScript Logic: Poorly-designed or incorrect use of onBlur, onChange, or onFocus can break your apps navigation flow and cause unintended consequences for keyboard navigation.

Avoid using custom logic wherever possible and rely on built-in structure and methods for navigation. When adding custom logic, be extremely careful and test thoroughly.

Color and Contrast

Don't rely solely on color to convey information and ensure sufficient contrasting colors between text and background or foreground elements so that anyone who is visually impaired can successfully see and differentiate parts of your application.

"
Key Point:

Do not rely on color alone to signify meaning.

Colors in UI

Many people are colorblind, and specifically, many people are red-green colorblind. So when relying on color alone to convey meaning, such as confirm/continue (green) and cancel/stop (red), you are leaving these users in darkness. When using red, green, or other colors in manners like this, be sure to supply icons, words, description, patterns, or other visual indicators to support these meanings. This way, colorblind users can still participate in the app without being misled, misinformed, or left behind. No colorblind left behind!

In addition to these considerations, you should also check to make sure that your focus state relies on more than color alone to stand out. A common industry standard for focus state is often a dotted outline .

There are colorblindness simulator tools that you can use to test for color accessibility compliance:

  • Coblis — Color Blindness Simulator
  • Skynet Technologies Colorblindness Simulator
  • Whocanuse Colorblindness and Contrast Assessment

Contrast in UI

The purpose of using color contrast ratios in web accessibility is simply to make sure your content is legible by those who have visual impairments and those who do not have visual impairments. All users can benefits from using sufficient color contrast between the background, foreground, and text, especially as we use devices with small screens so heavily in everyday life.

  • Maintain contrast ratio of at least 4.5:1 for normal text (Level AA)
  • Maintain contrast ratio of at least 3:1 for large text (18pt+ or 14pt+ bold)

Form Accessibility

Forms are one of the most important elements to check for accessibility issues, as they can be surprisingly complex and are typically a main point of entry for interaction with your organization. Forms must be properly labeled and provide clear error messaging.

  • Associate labels with form controls using the for attribute or implicit labeling
  • Use <fieldset> and <legend> for related form groups
  • Provide clear, specific error messages
  • Indicate required fields clearly
  • Provide helpful instructions and examples
  • Allow users to review and correct errors before submission

Content Structure

Well-structured content is easier to navigate and understand.

  • Use a single <h1> per page
  • Maintain proper heading hierarchy (don't skip levels)
  • Use lists for list content
  • Break up long content with headings and sections
  • Use paragraphs for text blocks
  • Provide clear, descriptive link text (avoid "click here")

Multimedia Accessibility

Audio and video content must be accessible to all users.

  • Provide captions for all video content
  • Provide transcripts for audio content
  • Provide audio descriptions for video when visual information isn't described in audio
  • Ensure media players are keyboard accessible
  • Allow users to control playback (play, pause, stop)

Responsive and Flexible Design

Content should work across different devices and screen sizes.

  • Use relative units (em, rem, %) instead of fixed pixels
  • Ensure content reflows properly at different zoom levels
  • Test at 200% zoom level
  • Avoid horizontal scrolling
  • Ensure touch targets are at least 44x44 pixels

ARIA When Necessary

Use ARIA (Accessible Rich Internet Applications) to enhance accessibility when HTML alone isn't sufficient.

  • Use ARIA labels and descriptions when native HTML isn't enough
  • Use ARIA roles for custom components
  • Use ARIA states and properties to communicate dynamic content
  • Don't use ARIA when native HTML provides the same functionality
  • Test with screen readers to ensure ARIA is working correctly

Performance and Accessibility

Fast-loading pages benefit all users, especially those with slower connections or assistive technologies.

  • Optimize images and media files
  • Minimize JavaScript and CSS
  • Ensure critical content loads first
  • Test on slower connections and devices

    • Lazy Loading

    While lazy loading has become increasingly popular over the last decade, it can create very poor usability. Try navigating to the very last item in a list of thousands or tens of thousands of lazy loaded items and you will quickly understand why. I would STRONGLY recommend against using lazy loading for this reason. Any performance gains brought by lazy loading are outweighed by performance losses in latency and an endlessly (pun intended) frustrating experience for the user, especially on a slow connection. These issues are only exacerbated when considering user accessibility. If it is difficult for a typical user to navigate, you can assume it will be even more difficult for users with mobility issues to use. Anything that can be lazy loaded can be paginated. Get creative and come up with an alterative interaction.
