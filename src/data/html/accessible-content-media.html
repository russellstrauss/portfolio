Accessible Content & Media

Creating accessible content and media ensures that all users can access and understand your information, regardless of how they consume it. This guide covers best practices for text, images, video, audio, and other media types.

Text Content

Writing for Clarity

  • Use plain, clear language appropriate for your audience
  • Avoid jargon and technical terms without explanation
  • Write in short, clear sentences
  • Use active voice when possible
  • Break up long paragraphs
  • Use headings to organize content
  • Provide summaries for complex topics

Link Text

  • Write descriptive link text that makes sense out of context
  • Avoid generic phrases like "click here" or "read more"
  • Indicate when links open in new windows
  • Make link purpose clear from the link text alone
  • Example: "Download the accessibility guidelines (PDF)" instead of "Click here"

Abbreviations and Acronyms

  • Spell out abbreviations and acronyms on first use
  • Use the <abbr> element with a title attribute
  • Provide explanations for technical terms
  • Example: <abbr title="Web Content Accessibility Guidelines">WCAG</abbr>

Images

Alternative Text Guidelines

  • Decorative images: Use empty alt="" (alt attribute present but empty)
  • Informative images: Describe the content and purpose
  • Functional images: Describe the function (e.g., "Search" for search icon)
  • Images of text: Include the text in alt attribute (avoid images of text when possible)
  • Complex images: Provide brief alt text and detailed description nearby

Writing Good Alt Text

  • Be specific and concise (aim for 125 characters or less)
  • Describe what's important about the image in context
  • Avoid redundant phrases like "image of" or "picture of"
  • Include text that appears in the image
  • Consider the image's purpose in the content
  • Example: "Bar chart showing 45% increase in accessibility compliance"

Complex Images

  • Charts and graphs: Describe the data and trends
  • Maps: Describe locations and relationships
  • Diagrams: Explain the concept or process
  • Provide detailed descriptions in surrounding text or longdesc
  • Consider providing data in table format as alternative

Video Content

Captions

  • Provide captions for all video content
  • Captions should be accurate and synchronized
  • Include speaker identification when relevant
  • Include important sound effects and music descriptions
  • Ensure captions don't obscure important visual information
  • Provide option to turn captions on/off

Audio Descriptions

  • Provide audio descriptions when visual information isn't described in audio
  • Describe important visual elements, actions, and scene changes
  • Integrate descriptions naturally into narration when possible
  • Consider extended audio descriptions for complex visuals

Transcripts

  • Provide full transcripts for all video content
  • Include speaker names and timestamps
  • Describe important visual elements in transcripts
  • Make transcripts easy to find and download

Accessible Video Players

  • Ensure players are keyboard accessible
  • Provide clear controls (play, pause, volume, captions)
  • Support standard keyboard shortcuts
  • Ensure controls have sufficient size and contrast
  • Provide accessible settings menus

Audio Content

Podcasts and Audio Recordings

  • Provide transcripts for all audio content
  • Include speaker identification
  • Describe important sound effects or music
  • Make transcripts easy to find and access
  • Consider providing chapter markers for long content

Audio Controls

  • Don't auto-play audio
  • Provide clear play/pause controls
  • Allow users to adjust volume
  • Provide option to stop audio
  • Ensure controls are keyboard accessible

Documents (PDF, Word, etc.)

Accessible PDFs

  • Use proper heading structure
  • Add alt text to images
  • Ensure proper reading order
  • Use tags for structure
  • Provide bookmarks for navigation
  • Ensure text is selectable (not just images)
  • Test with screen readers

Word Documents

  • Use built-in heading styles
  • Add alt text to images
  • Use proper list formatting
  • Ensure proper table structure
  • Use descriptive hyperlink text
  • Check accessibility with built-in checker

Data Tables

Simple Tables

  • Use proper table structure (table, thead, tbody, th, td)
  • Use scope attribute for header cells
  • Provide table captions for context
  • Ensure tables are responsive on mobile

Complex Tables

  • Use headers and id attributes to associate cells
  • Provide clear table summaries
  • Break complex tables into simpler tables when possible
  • Consider alternative presentation methods

Forms and Interactive Content

Form Labels and Instructions

  • Provide clear, descriptive labels
  • Include helpful instructions
  • Show required field indicators
  • Provide examples for complex inputs
  • Group related fields visually and semantically

Error Messages

  • Write clear, specific error messages
  • Explain what went wrong
  • Provide suggestions for correction
  • Associate errors with form fields
  • Allow users to review and correct before submission

Dynamic Content

Content Updates

  • Announce important content changes to screen readers
  • Use ARIA live regions appropriately
  • Provide status updates for long operations
  • Ensure users can access updated content

Time-Sensitive Content

  • Avoid time limits when possible
  • Provide option to extend or disable time limits
  • Warn users before time expires
  • Allow users to save progress

Content Organization

Headings

  • Use proper heading hierarchy (h1, h2, h3, etc.)
  • Don't skip heading levels
  • Use one h1 per page
  • Use headings to organize content, not for styling

Lists

  • Use lists for list content
  • Use ordered lists (ol) for sequential items
  • Use unordered lists (ul) for non-sequential items
  • Nest lists properly when needed

Language and Localization

Language Declaration

  • Declare the primary language of the page
  • Indicate language changes within content
  • Use lang attribute on html element and content elements
  • Example: <html lang="en"> or <p lang="es">Spanish text</p>

Content Review Checklist

  • All images have appropriate alt text
  • Videos have captions and transcripts
  • Audio has transcripts
  • Links are descriptive and meaningful
  • Headings are used properly
  • Content is written clearly
  • Abbreviations are explained
  • Tables are properly structured
  • Forms have clear labels and instructions
  • Language is declared
